[7장 전체 흐름]
시프트·회전 → 비트 연산 응용 → 곱셈·나눗셈 → 큰 수의 덧셈·뺄셈 → 10진수 보정

1. Shift & Rotate 명령어 
------------------------------------------------------------
명령어   기능                     꼭 기억할 점
SHL      왼쪽 시프트              오른쪽 빈자리를 0으로 채움
SAL      산술 왼쪽 시프트         SHL과 동작 동일
SHR      논리 오른쪽 시프트       왼쪽 빈자리를 0으로 채움
SAR      산술 오른쪽 시프트       왼쪽을 기존 부호 비트로 채움
ROL      왼쪽 회전                밀려난 최상위 비트가 반대편으로 돌아옴
ROR      오른쪽 회전              밀려난 최하위 비트가 반대편으로 돌아옴
RCL      CF를 포함한 왼쪽 회전    기존 CF가 최하위 비트에 들어감
RCR      CF를 포함한 오른쪽 회전  기존 CF가 최상위 비트에 들어감
SHLD     이중 정밀 왼쪽 시프트    다른 원본의 상위 비트로 빈자리 채움
SHRD     이중 정밀 오른쪽 시프트  다른 원본의 하위 비트로 빈자리 채움

- SHL/SHR/SAR에서 바깥으로 밀려난 마지막 비트는 CF에 저장됨.
- SHL로 1비트 왼쪽 이동하면, 넘침이 없는 범위에서 2배 효과.
- SHR로 1비트 오른쪽 이동하면, 부호 없는 정수에서 2로 나눈 몫의 효과.
- 음수의 부호를 유지해야 하는 오른쪽 시프트는 SAR 사용.
- ROL/ROR은 비트가 없어지지 않고 반대편으로 돌아옴.
- RCL/RCR은 CF도 회전 경로에 들어가므로 ROL/ROR과 다름.
- 시프트·회전 횟수가 1보다 크면 OF 값은 정의되지 않음(강의자료 기준).

예제 A)
    mov bl,8Fh         ; 10001111b
    shl bl,1          ; BL=00011110b=1Eh, CF=1

예제 B)
    mov al,80h        ; 10000000b
    shr al,1          ; AL=40h (01000000b)
    mov al,80h
    sar al,1          ; AL=C0h (11000000b, 부호 비트 유지)

[핵심 구분] SHR은 왼쪽에 0, SAR은 왼쪽에 기존 최상위 비트.

2. 시프트 응용 
------------------------------------------------------------
(1) 여러 바이트를 하나의 큰 수처럼 이동
    상위 바이트를 SHR로 이동 → 아래 바이트를 RCR로 이동.
    CF를 통해 상위 바이트에서 밀려난 비트를 다음 바이트로 넘김.

(2) 시프트를 이용한 곱셈
    36 = 32 + 4 = 2^5 + 2^2
    123 × 36 = (123 << 5) + (123 << 2) = 4428

    mov eax,123
    mov ebx,eax
    shl eax,5
    shl ebx,2
    add eax,ebx      ; EAX=4428 (10진수)

(3) 2진수를 ASCII '0'/'1' 문자열로 변환
    SHL로 최상위 비트를 CF에 내보냄 → CF=1이면 문자 '1', 아니면 '0'.
    이를 32번 반복하면 32비트의 이진 문자열을 만들 수 있음.

(4) 비트 필드 추출
    파일 날짜 같은 비트 단위 데이터는 SHR과 AND 마스크로
    연도·월·일 등 필요한 부분만 꺼낼 수 있음.

3. MUL / IMUL 곱셈 
------------------------------------------------------------
MUL  : 부호 없는 곱셈
IMUL : 부호 있는 곱셈

피연산자 크기       암묵적 피승수       결과 저장 위치
8비트              AL                  AX
16비트             AX                  DX:AX
32비트             EAX                 EDX:EAX

- DX:AX = DX가 상위 16비트, AX가 하위 16비트.
- EDX:EAX = EDX가 상위 32비트, EAX가 하위 32비트.
- MUL은 단일 피연산자 형식을 사용함.
- IMUL은 단일·2개·3개 피연산자 형식을 사용할 수 있음.
- IMUL의 2·3피연산자 형식은 목적지 크기에 맞춰 결과가 잘릴 수 있음.
- 상위 자리가 버려지는 곱셈은 CF/OF 확인이 중요함.

예제)
    mov al,5
    mov bl,10h
    mul bl             ; AX = 0050h

    mov ax,-16
    mov bx,2
    imul bx            ; DX:AX = -32 (부호 있는 곱셈)

[시험 포인트] MUL/IMUL 뒤 결과를 EAX만 보지 말고 AX, DX:AX,
EDX:EAX 중 어디에 저장되는지 먼저 판단해야 함.

4. DIV / IDIV 나눗셈 
------------------------------------------------------------
DIV  : 부호 없는 나눗셈
IDIV : 부호 있는 나눗셈

제수 크기       나누어지는 값       몫       나머지
8비트          AX                  AL       AH
16비트         DX:AX               AX       DX
32비트         EDX:EAX             EAX      EDX

예제)
    mov ax,0083h
    mov bl,2
    div bl             ; AL=41h(몫), AH=01h(나머지)

32비트 양수 나눗셈에서 피제수가 EAX 범위에만 있다면
보통 EDX를 0으로 초기화해야 함.
    mov edx,0
    mov eax,100
    mov ebx,3
    div ebx            ; EAX=33, EDX=1

부호 있는 수를 IDIV로 나눌 때는 피제수를 부호 확장.
    CBW : AL → AX (8→16비트 부호 확장)
    CWD : AX → DX:AX (16→32비트 부호 확장)
    CDQ : EAX → EDX:EAX (32→64비트 부호 확장)

예제)
    mov eax,-101
    cdq
    mov ebx,2
    idiv ebx           ; EAX=-50, EDX=-1

주의)
- 0으로 나누면 오류 발생: DIV/IDIV 전에 제수가 0인지 검사.
- 몫이 지정된 레지스터에 들어가지 못할 정도로 크면 나눗셈 예외 발생.
- DIV/IDIV 실행 후 산술 상태 플래그는 정의되지 않음.

5. ADC / SBB 큰 수 연산 
------------------------------------------------------------
ADC dest,src : dest = dest + src + CF
SBB dest,src : dest = dest - src - CF

- ADC는 낮은 자리 덧셈의 올림수(Carry)를 윗자리로 전달.
- SBB는 낮은 자리 뺄셈의 빌림(Borrow)을 윗자리로 전달.
- 64비트 이상의 수를 32비트 단위로 나눠 계산할 때 사용.

예제: 64비트 값의 하위·상위 DWORD 덧셈
    add eax,ebx      ; 낮은 32비트끼리 더함
    adc edx,ecx      ; 높은 32비트 + 낮은 자리의 CF

예제: 64비트 값의 하위·상위 DWORD 뺄셈
    sub eax,ebx
    sbb edx,ecx

[핵심] 윗자리 연산은 ADD/SUB가 아니라 ADC/SBB로 CF를 반영.

6. ASCII / Unpacked Decimal 보정 
------------------------------------------------------------
명령어     의미
AAA        덧셈 후 보정 (ASCII Adjust after Addition)
AAS        뺄셈 후 보정 (ASCII Adjust after Subtraction)
AAM        곱셈 후 보정 (ASCII Adjust after Multiplication)
AAD        나눗셈 전 보정 (ASCII Adjust before Division)

- ASCII 숫자 '0'~'9'는 30h~39h 형태.
- Unpacked decimal은 한 바이트에 한 자리의 10진 숫자를 보관하며
  상위 4비트가 0000인 형태.
- 보정 명령어는 일반적인 이진 덧셈/뺄셈 결과를 10진 자리로 맞춤.

예제(강의자료의 AAA 개념)
    mov ah,0
    mov al,'8'
    add al,'2'
    aaa              ; AX=0100h (10진수 10의 자리/1의 자리)
    or ax,3030h      ; AX=3130h ('1','0' 문자 코드)

7. Packed Decimal 보정 
------------------------------------------------------------
Packed decimal : 한 바이트에 10진 숫자 두 자리(각각 4비트).
DAA : ADD/ADC 뒤 packed decimal 결과 보정.
DAS : SUB/SBB 뒤 packed decimal 결과 보정.

예제)
    mov al,35h
    add al,48h        ; AL=7Dh
    daa               ; AL=83h (packed decimal 83)

    mov al,85h
    sub al,48h        ; AL=3Dh
    das               ; AL=37h (packed decimal 37)
