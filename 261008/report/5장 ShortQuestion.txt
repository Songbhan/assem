1번
32비트 범용 레지스터 8개를 모두 스택에 저장하는 명령어는 무엇인가?

[정답]
PUSHAD

[풀이]
PUSHAD는 32비트 범용 레지스터 8개를 스택에 저장한다.
대상: EAX, ECX, EDX, EBX, ESP, EBP, ESI, EDI
(실제 저장 순서는 위 순서이며, ESP에는 PUSHAD 실행 전의 값이 저장된다.)
32비트 모드에서는 스택에 총 32바이트가 사용된다.


2번
32비트 EFLAGS 레지스터를 스택에 저장하는 명령어는 무엇인가?

[정답]
PUSHFD

[풀이]
PUSHFD는 32비트 EFLAGS의 값을 스택에 저장한다.
32비트 값을 PUSH하므로 ESP는 4 감소한다.


3번
스택에 저장된 값을 32비트 EFLAGS 레지스터로 복원하는 명령어는 무엇인가?

[정답]
POPFD

[풀이]
POPFD는 스택 맨 위의 32비트 값을 EFLAGS로 복원한다.
POP을 수행하므로 ESP는 4 증가한다.
단, 일부 플래그는 실행 권한 등에 따라 변경이 제한될 수 있다.


4번
NASM이라는 어셈블러는 PUSH 명령어에 여러 개의 특정 레지스터를
나열할 수 있다고 한다. 이런 방식이 MASM의 PUSHAD보다
더 좋은 이유는 무엇인가?

문제에서 제시한 NASM 예시:
PUSH EAX EBX ECX

[정답]
필요한 레지스터만 선택해서 스택에 저장할 수 있기 때문이다.

[풀이]
PUSHAD는 8개의 32비트 범용 레지스터를 전부 저장한다.
반면 문제에 제시된 방식은 EAX, EBX, ECX처럼
실제로 필요한 레지스터만 지정할 수 있다.

따라서:
1) 스택 공간을 덜 사용한다.
2) 불필요한 메모리 접근을 줄일 수 있다.

참고: 위 NASM 표기는 문제에서 제시한 예시를 그대로 옮긴 것이다.


5번
PUSH 명령어가 존재하지 않는다고 가정하자.
PUSH EAX와 동일한 효과를 내는 다른 명령어 두 개를 작성하라.

[정답]
sub esp,4
mov DWORD PTR [esp],eax

[풀이]
PUSH EAX의 동작은 다음과 같다.

1) ESP를 4 감소시킨다.
2) 감소된 ESP가 가리키는 메모리 주소에 EAX(4바이트)를 저장한다.

따라서:
sub esp,4                  ; 스택 공간 4바이트 확보
mov DWORD PTR [esp],eax    ; 그 공간에 EAX 저장

이 두 명령어로 PUSH EAX와 같은 효과를 낼 수 있다.


6번 (True/False)
RET 명령어는 스택의 맨 위 값을 명령어 포인터에 POP한다.

[정답]
True (참)

[풀이]
32비트 코드에서 일반적인 near RET는
스택 맨 위에 있는 4바이트 복귀 주소를 EIP로 가져온다.
그다음 ESP를 4 증가시킨다.

CALL: 복귀 주소를 스택에 저장한 후 이동
RET : 스택의 복귀 주소를 꺼내 그곳으로 이동


7번 (True/False)
Microsoft 어셈블러에서 NESTED 연산자를 프로시저 선언에 사용하지 않으면
중첩 프로시저 호출이 허용되지 않는다.

[정답]
False (거짓)

[풀이]
한 프로시저 안에서 다른 프로시저를 CALL하는 중첩 호출은 가능하다.

예:
main PROC
    call ProcA
    ret
main ENDP

ProcA PROC
    call ProcB
    ret
ProcA ENDP

ProcB PROC
    ret
ProcB ENDP

이처럼 NESTED 연산자가 없어도 프로시저가 다른 프로시저를 호출할 수 있다.
(위 코드는 호출 구조를 설명하기 위한 예시이다.)


8번 (True/False)
보호 모드(protected mode)에서 각 프로시저 호출은
최소 4바이트의 스택 공간을 사용한다.

[정답]
True (참)

[풀이]
교재에서 사용하는 32비트 near CALL은
다음에 실행할 명령어의 주소(복귀 주소) 4바이트를 스택에 저장한다.

CALL을 실행하면:
ESP = ESP - 4
[ESP] = 복귀 주소

매개변수나 추가로 저장한 레지스터가 있으면
스택 공간을 더 사용할 수 있다.


9번 (True/False)
프로시저에 32비트 매개변수를 전달할 때
ESI와 EDI 레지스터는 사용할 수 없다.

[정답]
False (거짓)

[풀이]
ESI와 EDI도 32비트 범용 레지스터이므로
매개변수나 주소를 전달하는 데 사용할 수 있다.

예:
mov esi,OFFSET array    ; 배열 시작 주소 전달
mov ecx,LENGTHOF array  ; 배열 원소 개수 전달
call ArraySum

단, 일반적으로 ESI/EDI를 변경하는 프로시저는
호출한 쪽에서 필요로 하는 원래 값을 보존해야 한다.


10번 (True/False)
5.2.5절의 ArraySum 프로시저는
어떤 DWORD 배열이든 가리키는 포인터를 전달받을 수 있다.

[정답]
True (참)

[풀이]
ArraySum은 특정 배열 이름을 직접 사용하는 대신
ESI에 들어 있는 배열 시작 주소를 사용한다.
ECX는 처리할 원소 개수이다.

예:
mov esi,OFFSET array
mov ecx,LENGTHOF array
call ArraySum

이렇게 배열의 주소와 원소 개수를 전달하면
DWORD 배열을 순회하며 합계를 계산할 수 있다.
단, ESI가 유효한 DWORD 배열을 가리키고
ECX가 처리 가능한 올바른 원소 개수여야 한다.


11번 (True/False)
USES 연산자를 사용하면 프로시저 안에서 변경하는
레지스터들을 나열할 수 있다.

[정답]
True (참)

[풀이]
USES 뒤에 프로시저가 저장하고 복원해야 할 레지스터를 적을 수 있다.

예:
ArraySum PROC USES esi ecx
    mov eax,0
    ; 배열 합산 코드
    ret
ArraySum ENDP

USES esi ecx는 개념적으로 다음과 같다.
프로시저 시작: push esi / push ecx
프로시저 종료: pop ecx / pop esi

주의:
USES는 '자동으로 변경된 레지스터를 찾아내는 기능'이 아니다.
프로그래머가 보존할 레지스터를 직접 나열한다.
EAX에 반환값을 넣는 프로시저에서는 EAX까지 보존하면
반환하려던 값이 덮어써질 수 있으므로 주의해야 한다.


12번 (True/False)
USES 연산자는 PUSH 명령어만 자동 생성하므로
POP 명령어는 프로그래머가 직접 작성해야 한다.

[정답]
False (거짓)

[풀이]
USES는 지정한 레지스터를 저장하는 PUSH뿐 아니라
복원하는 POP도 자동 생성한다.

예:
Example PROC USES ebx esi
    ; 작업 코드
    ret
Example ENDP

개념적인 실행 흐름:
push ebx
push esi
; 작업 코드
pop esi
pop ebx
ret

따라서 PUSH와 POP를 모두 직접 쓸 필요가 없다.


13번 (True/False)
USES 지시어에서 레지스터 이름들은 반드시 쉼표(,)로 구분해야 한다.

[정답]
False (거짓)

[풀이]
USES의 레지스터 목록은 쉼표가 아니라 공백으로 구분한다.

올바른 예:
ArraySum PROC USES esi ecx

잘못된 예:
ArraySum PROC USES esi,ecx


14번
5.2.5절의 ArraySum 프로시저가 16비트 WORD 배열의 합계를
계산하도록 하려면 어떤 명령어들을 수정해야 하는가?
수정된 ArraySum을 만들고 테스트하라.

[정답]
기존의 DWORD(4바이트) 읽기 부분을
WORD(2바이트) 읽기로 바꾸고,
ESI가 2바이트씩 증가하도록 수정한다.

기존 핵심 코드:
L1:
    add eax,[esi]
    add esi,TYPE DWORD
    loop L1

수정 핵심 코드 (부호 없는 WORD 기준):
L1:
    movzx edx,WORD PTR [esi]
    add eax,edx
    add esi,TYPE WORD
    loop L1

[전체 코드]
INCLUDE Irvine32.inc

.data
array WORD 1000,2000,3000,4000
sum DWORD ?

.code
main PROC
    mov esi,OFFSET array
    mov ecx,LENGTHOF array

    call ArraySum
    mov sum,eax

    call WriteDec
    call Crlf

    exit
main ENDP

ArraySum PROC
    push esi
    push ecx
    push edx

    mov eax,0

L1:
    movzx edx,WORD PTR [esi]
    add eax,edx
    add esi,TYPE WORD
    loop L1

    pop edx
    pop ecx
    pop esi
    ret
ArraySum ENDP

END main

[예상 실행 결과]
화면 출력: 10000
WriteDec 호출 전 EAX의 합계: 10000 (10진수)

[풀이]
WORD는 2바이트이고 DWORD는 4바이트이다.

movzx edx,WORD PTR [esi]
-> ESI가 가리키는 WORD(2바이트)를 읽고
   상위 비트를 0으로 채워 EDX에 저장한다.

add eax,edx
-> 읽은 값을 합계용 EAX에 누적한다.

add esi,TYPE WORD
-> 다음 WORD 원소로 이동한다. 즉 ESI가 2 증가한다.

ECX는 배열 원소 개수(4)이므로 LOOP는 4번 수행된다.
합계 = 1000 + 2000 + 3000 + 4000 = 10000

EDX를 새로 사용하기 때문에 PUSH/POP으로 원래 값을 보존한다.
이 코드는 부호 없는 WORD 배열을 대상으로 한다.


15번
다음 명령어들을 실행한 후 EAX의 최종 값은 무엇인가?

push 5
push 6
pop eax
pop eax

[정답]
EAX = 5 (00000005h)

[풀이]
스택은 LIFO(Last In, First Out) 구조이다.
즉, 나중에 넣은 값이 먼저 나온다.

1) push 5   -> 스택에 5 저장
2) push 6   -> 5 위에 6 저장
3) pop eax  -> 맨 위의 6을 꺼내 EAX = 6
4) pop eax  -> 다음 5를 꺼내 EAX = 5

최종:
EAX = 5


16번
다음 코드가 실행되었을 때 발생하는 현상에 대한
올바른 설명을 고르라.

1:  main PROC
2:      push 10
3:      push 20
4:      call Ex2Sub
5:      pop eax
6:      INVOKE ExitProcess,0
7:  main ENDP
8:
9:  Ex2Sub PROC
10:     pop eax
11:     ret
12: Ex2Sub ENDP

선택지:
a. 6번 줄에서 EAX는 10이다.
b. 10번 줄에서 런타임 오류로 프로그램이 종료된다.
c. 6번 줄에서 EAX는 20이다.
d. 11번 줄에서 런타임 오류로 프로그램이 종료된다.

[정답]
d. 11번 줄에서 런타임 오류로 프로그램이 종료된다.

[풀이]
중요: CALL은 복귀 주소를 먼저 스택에 PUSH한다.

1) push 10
   스택 맨 위 = 10

2) push 20
   스택 맨 위 = 20

3) call Ex2Sub
   복귀 주소(5번 줄의 주소)를 스택에 PUSH한다.
   스택 맨 위 = 복귀 주소

4) Ex2Sub의 pop eax (10번 줄)
   복귀 주소를 EAX로 꺼내버린다.
   스택 맨 위 = 20

5) ret (11번 줄)
   RET은 맨 위 값 20을 복귀 주소로 해석하여
   주소 00000014h로 이동하려 한다.
   일반적인 보호 모드 실행 환경에서 유효하지 않은 주소이므로 오류가 난다.

따라서 교재의 의도된 정답은 d번이다.
(정확한 오류 발생 양상은 실행 환경의 메모리 보호 설정에 영향을 받는다.)


17번
다음 코드가 실행되었을 때 발생하는 현상에 대한
올바른 설명을 고르라.

1:  main PROC
2:      mov eax,30
3:      push eax
4:      push 40
5:      call Ex3Sub
6:      INVOKE ExitProcess,0
7:  main ENDP
8:
9:  Ex3Sub PROC
10:     pusha
11:     mov eax,80
12:     popa
13:     ret
14: Ex3Sub ENDP

선택지:
a. 6번 줄에서 EAX는 40이다.
b. 6번 줄에서 런타임 오류로 프로그램이 종료된다.
c. 6번 줄에서 EAX는 30이다.
d. 13번 줄에서 런타임 오류로 프로그램이 종료된다.

[정답]
c. 6번 줄에서 EAX는 30이다.

[풀이]
1) mov eax,30
   EAX = 30

2) push eax / push 40
   스택에 30과 40을 차례로 저장한다.

3) call Ex3Sub
   복귀 주소를 스택에 저장하고 Ex3Sub로 이동한다.

4) pusha
   EAX를 포함한 32비트 범용 레지스터 값을 스택에 저장한다.
   (32비트 코드에서의 PUSHA는 PUSHAD와 같은 크기로 동작한다.)

5) mov eax,80
   EAX = 80

6) popa
   저장해 둔 레지스터 값을 복원하므로 EAX = 30이 된다.

7) ret
   CALL이 저장한 복귀 주소로 정상 복귀한다.

따라서 6번 줄에 도달했을 때 EAX = 30이다.


18번
다음 코드가 실행되었을 때 발생하는 현상에 대한
올바른 설명을 고르라.

1:  main PROC
2:      mov eax,40
3:      push OFFSET Here
4:      jmp Ex4Sub
5:  Here:
6:      mov eax,30
7:      INVOKE ExitProcess,0
8:  main ENDP
9:
10: Ex4Sub PROC
11:     ret
12: Ex4Sub ENDP

선택지:
a. 7번 줄에서 EAX는 30이다.
b. 4번 줄에서 런타임 오류로 프로그램이 종료된다.
c. 6번 줄에서 EAX는 30이다.
d. 11번 줄에서 런타임 오류로 프로그램이 종료된다.

[정답]
a. 7번 줄에서 EAX는 30이다.

[풀이]
CALL과 JMP는 다르다.

CALL: 복귀 주소를 스택에 저장한 뒤 이동한다.
JMP : 복귀 주소를 저장하지 않고 이동한다.

하지만 이 코드에서는 JMP 이전에 복귀 주소를 직접 PUSH했다.

1) mov eax,40
   EAX = 40

2) push OFFSET Here
   Here의 주소를 스택에 저장한다.

3) jmp Ex4Sub
   Ex4Sub로 이동한다. (이때 추가 PUSH는 없다.)

4) Ex4Sub의 ret
   스택에서 Here의 주소를 꺼내 그곳으로 이동한다.

5) Here: mov eax,30
   EAX = 30

6) 7번 줄에 도달
   EAX는 여전히 30이다.

따라서 a번이다.


19번
다음 코드가 실행되었을 때 발생하는 현상에 대한
올바른 설명을 고르라.

1:  main PROC
2:      mov edx,0
3:      mov eax,40
4:      push eax
5:      call Ex5Sub
6:      INVOKE ExitProcess,0
7:  main ENDP
8:
9:  Ex5Sub PROC
10:     pop eax
11:     pop edx
12:     push eax
13:     ret
14: Ex5Sub ENDP

선택지:
a. 6번 줄에서 EDX는 40이다.
b. 13번 줄에서 런타임 오류로 프로그램이 종료된다.
c. 6번 줄에서 EDX는 0이다.
d. 11번 줄에서 런타임 오류로 프로그램이 종료된다.

[정답]
a. 6번 줄에서 EDX는 40이다.

[풀이]
CALL 직후 스택의 맨 위에서부터:
복귀 주소
40

Ex5Sub 내부:

1) pop eax
   복귀 주소를 EAX로 꺼낸다.
   스택 맨 위 = 40

2) pop edx
   40을 EDX로 꺼낸다.
   EDX = 40

3) push eax
   복귀 주소를 다시 스택에 넣는다.

4) ret
   복귀 주소를 꺼내 main의 6번 줄로 정상 복귀한다.

따라서:
EDX = 40
정답 = a번


20번
다음 코드가 실행되면 array에 어떤 값들이 저장되는가?

.data
array DWORD 4 DUP(0)

.code
main PROC
    mov eax,10
    mov esi,0
    call proc_1
    add esi,4
    add eax,10
    mov array[esi],eax
    INVOKE ExitProcess,0
main ENDP

proc_1 PROC
    call proc_2
    add esi,4
    add eax,10
    mov array[esi],eax
    ret
proc_1 ENDP

proc_2 PROC
    call proc_3
    add esi,4
    add eax,10
    mov array[esi],eax
    ret
proc_2 ENDP

proc_3 PROC
    mov array[esi],eax
    ret
proc_3 ENDP

[정답]
array[0] = 10
array[1] = 20
array[2] = 30
array[3] = 40

최종 배열 (10진수):
10, 20, 30, 40

[풀이]
처음:
EAX = 10
ESI = 0

호출 순서:
main -> proc_1 -> proc_2 -> proc_3

실제로 값을 저장하는 순서는 가장 안쪽의 proc_3부터이다.

1) proc_3
   mov array[esi],eax
   ESI = 0, EAX = 10
   array+0에 10 저장 -> array[0] = 10
   ret

2) proc_2로 복귀
   add esi,4   -> ESI = 4
   add eax,10 -> EAX = 20
   mov array[esi],eax
   array+4에 20 저장 -> array[1] = 20
   ret

3) proc_1로 복귀
   add esi,4   -> ESI = 8
   add eax,10 -> EAX = 30
   mov array[esi],eax
   array+8에 30 저장 -> array[2] = 30
   ret

4) main으로 복귀
   add esi,4   -> ESI = 12
   add eax,10 -> EAX = 40
   mov array[esi],eax
   array+12에 40 저장 -> array[3] = 40

DWORD 원소 하나의 크기는 4바이트이다.
따라서 array+0, +4, +8, +12가 각각
첫째, 둘째, 셋째, 넷째 원소를 가리킨다.

최종:
array = 10, 20, 30, 40
