8장 Advanced Procedures
8.10.1 Short Answer (1~9번) - 정답 및 풀이
기준: 사용자가 올린 8.10.1 문제 사진과 8장 강의자료 (32비트 MASM, STDCALL 기준)

============================================================
1번. 스택 매개변수와 지역변수가 있는 프로시저의 에필로그(epilogue)에 속하는 명령문은?
[정답]
- 필요하다면 보존했던 레지스터를 POP으로 복원한다.
- mov esp,ebp / pop ebp 로 지역변수 영역 및 이전 스택 프레임을 정리한다.
- ret 또는 ret N 으로 호출 지점에 복귀한다.
[풀이]
에필로그는 프로시저를 끝내기 직전 스택 프레임을 원상복구하는 부분이다.
보존 레지스터를 복원하고 지역변수 영역을 없앤 뒤 원래 EBP로 되돌린다.
STDCALL이라면 ret N 또는 MASM이 자동 생성한 종료 코드로 매개변수 공간을 정리한다.

============================================================
2번. C 함수가 32비트 정수를 반환할 때 반환값은 어디에 저장되는가?
[정답]
EAX 레지스터.
[풀이]
32비트 x86 C 호출 규약에서 32비트 정수 결과는 EAX로 반환한다.

============================================================
3번. STDCALL 호출 규약에서는 프로시저 호출 후 스택을 어떻게 정리하는가?
[정답]
호출된 프로시저(피호출자)가 매개변수 공간을 정리한다.
[풀이]
예: 인수 두 개(각 DWORD 4바이트)를 받았다면 ret 8로 복귀한다.
RET가 복귀 주소를 꺼내고 ESP에 8을 추가하여 인수 공간까지 없앤다.
CDECL과 달리 호출자가 add esp,8을 직접 실행하지 않는다.

============================================================
4번. LEA 명령어가 OFFSET 연산자보다 강력한 이유는?
[정답]
LEA는 레지스터를 포함하는 주소 계산식의 유효 주소를 실행 중 계산할 수 있다.
반면 OFFSET은 어셈블 시점에 결정되는 주소 상수를 구한다.
[풀이]
lea esi,[ebx+edi*4+8]   ; 레지스터 값에 따라 변하는 주소 계산
mov esi,OFFSET array    ; 고정된 배열 시작 주소 로드
LEA는 해당 메모리에 저장된 값을 읽는 것이 아니라 주소를 계산한다.

============================================================
5번. 8.2.3절의 C++ 예에서 int형 변수는 스택 공간을 얼마나 사용하는가?
[정답]
4바이트.
[풀이]
교재의 32비트 C++ 환경에서 int는 32비트(4바이트)이다.
지역변수 int x와 int y를 만들면 각각 보통 [EBP-4], [EBP-8]을 쓴다.

============================================================
6번. C 호출 규약(CDECL)이 STDCALL에 비해 가질 수 있는 장점은?
[정답]
호출자가 스택 인수들을 정리하므로 가변 인수 개수(variadic) 함수에 적합하다.
[풀이]
printf처럼 인수 개수가 달라지는 함수는 호출자가 실제로 전달한 인수 개수를
알기 때문에 스택 정리를 맡을 수 있다. 다만 호출 지점마다 정리 코드가 필요하다.

============================================================
7번. 참/거짓: PROC 지시어를 사용할 때 모든 매개변수를 반드시 같은 줄에 나열해야 한다.
[정답]
False (거짓).
[풀이]
PROC의 매개변수 목록은 쉼표로 구분하여 여러 줄에 걸쳐 적을 수 있다.
예:
AddTwo PROC,
    a:DWORD,
    b:DWORD

============================================================
8번. 참/거짓: 바이트 배열의 OFFSET이 들어 있는 변수를 WORD 배열 포인터를 기대하는
프로시저에 전달하면 어셈블러가 반드시 오류로 표시한다.
[정답]
False (거짓).
[풀이]
변수에 저장된 포인터 값이 단순한 DWORD라면 원래 어떤 데이터형을 가리키는지
타입 정보가 완전히 전달되지 않는다. 따라서 잘못된 포인터를 전달해도
어셈블러가 반드시 알아내는 것은 아니다. 실행 시 잘못된 크기로 접근할 수 있다.

============================================================
9번. 참/거짓: 참조 매개변수를 기대하는 프로시저에 즉시값을 전달하면 일반 보호 오류가
발생할 수 있다.
[정답]
True (참).
[풀이]
INVOKE Sub2,1000h 처럼 주소가 아닌 수를 포인터로 전달하면,
피호출 프로시저가 그 숫자를 주소로 사용하여 접근할 수 있다.
그 주소가 유효하지 않으면 일반 보호 오류 또는 접근 위반이 발생할 수 있다.
단, 실제 오류 발생 여부는 해당 주소의 매핑/권한에 따라 달라진다.

[핵심 암기]
[EBP] = 이전 EBP, [EBP+4] = 복귀 주소, [EBP+8] = 첫 번째 DWORD 인수
[EBP-4] 등 음수 오프셋 = 지역변수
CDECL: 호출자 정리 / STDCALL: 피호출자 정리
EAX: 32비트 정수 반환
