9장 Strings and Arrays
9.9.2 Algorithm Workbench (1~12번) - 정답 및 풀이
기준: 교재 문제 사진과 9장 강의자료 (기본 32비트 MASM + Irvine32).
코드는 별개의 예시이며 NotEqual 등의 분기 목적지는 실제 프로그램에서 정의한다. 실제 MASM 컴파일은 하지 않았다.


====================================================================
1번. 32비트 모드에서 base-index 피연산자의 예를 작성하라.
[정답]
mov eax,[ebx+esi]
[풀이]
EBX와 ESI를 더한 유효 주소의 DWORD를 읽는다.

====================================================================
2번. 32비트 모드에서 base-index-displacement 피연산자의 예를 작성하라.
[정답]
mov eax,[ebx+esi*4+8]
[풀이]
base=EBX, index=ESI, scale=4, displacement=8이다.

====================================================================
3번. 3행 4열 DWORD 배열에서 두 번째 행의 세 번째 열(행=1, 열=2)을 ESI와 EDI로 접근하라.
[정답]
; 행 우선 저장, myArray는 DWORD 배열
mov esi,1*4*TYPE myArray
mov edi,2
mov eax,myArray[esi+edi*TYPE myArray]
[풀이]
행 크기=4*4=16바이트, 열 오프셋=2*4=8바이트. 시작 주소에서 총 24바이트 떨어진 일곱 번째 원소이다.

====================================================================
4번. CMPSW를 사용하여 sourcew와 targetw 두 WORD 배열을 비교하라.
[정답]
; 두 배열의 원소 개수가 같고 1개 이상이라고 가정
cld
mov esi,OFFSET sourcew
mov edi,OFFSET targetw
mov ecx,LENGTHOF sourcew
repe cmpsw
jne NotEqual
; 같을 때 실행할 코드
[풀이]
CMPSW는 [ESI]-[EDI]로 비교하며 두 포인터를 2씩 이동시킨다. REPE는 다른 값이 나오거나 ECX=0이면 종료한다. 길이가 다를 수 있다면 길이도 확인해야 한다.

====================================================================
5번. SCASW로 wordArray에서 0100h를 찾고 일치한 원소의 주소를 EAX에 저장하라.
[정답]
cld
mov edi,OFFSET wordArray
mov ecx,LENGTHOF wordArray
mov ax,0100h
jecxz NotFound
repne scasw
jne NotFound
lea eax,[edi-2]
jmp Done
NotFound:
    xor eax,eax
Done:
[풀이]
찾으면 ZF=1이다. EDI는 비교 후 2바이트 증가하므로 2를 빼서 일치 원소 주소를 구한다. 찾지 못하면 이 예에서는 EAX=0으로 처리한다.

====================================================================
6번. Str_compare로 두 문자열 중 큰 문자열을 콘솔에 출력하라.
[정답]
INCLUDE Irvine32.inc
.data
str1 BYTE "APPLE",0
str2 BYTE "BANANA",0
.code
main PROC
    INVOKE Str_compare,ADDR str1,ADDR str2
    mov edx,OFFSET str1
    jae Display
    mov edx,OFFSET str2
Display:
    call WriteString
    call Crlf
    exit
main ENDP
END main
[풀이]
Str_compare는 ASCII 순서로 비교하며 CF=1이면 str1이 작다. MOV는 플래그를 변경하지 않는다. JAE는 CF=0(크거나 같음)일 때 이동한다. 예제 출력: BANANA.

====================================================================
7번. Str_trim을 호출하여 문자열 뒤쪽의 @ 문자를 모두 제거하라.
[정답]
INVOKE Str_trim,ADDR myString,'@'
[풀이]
예: "ABC@@@" → "ABC". 앞이나 중간의 @는 제거하지 않는다.

====================================================================
8번. Str_ucase를 수정하여 영어 대문자를 소문자로 변환하라.
[정답]
Str_lcase PROC USES eax esi, pString:PTR BYTE
    mov esi,pString
L1:
    mov al,[esi]
    test al,al
    jz L3
    cmp al,'A'
    jb L2
    cmp al,'Z'
    ja L2
    or BYTE PTR [esi],00100000b
L2:
    inc esi
    jmp L1
L3:
    ret
Str_lcase ENDP
[풀이]
ASCII 대문자 A~Z만 bit 5를 1로 만들어 소문자로 바꾼다. 다른 문자는 그대로 둔다.

====================================================================
9번. Str_trim 프로시저의 64비트 버전을 작성하라.
[정답]
; ml64, Windows x64 호출 규약
; RCX = 문자열 주소, DL = 제거할 문자
.code
Str_trim64 PROC
    mov rax,rcx
ScanEnd:
    cmp BYTE PTR [rax],0
    je TrimBack
    inc rax
    jmp ScanEnd
TrimBack:
    cmp rax,rcx
    je Finish
    cmp BYTE PTR [rax-1],dl
    jne Finish
    dec rax
    jmp TrimBack
Finish:
    mov BYTE PTR [rax],0
    ret
Str_trim64 ENDP
END
[풀이]
NULL의 위치를 찾고 뒤쪽에 연속된 문자를 제거한다. RCX=문자열 시작 주소, DL=제거 문자. RAX는 임시 포인터이다. 다른 함수를 호출하지 않는 leaf procedure로, 비휘발성 레지스터를 수정하지 않는다. 호출자는 Windows x64 규약에 따라 shadow space 및 스택 정렬을 확보한다.

====================================================================
10번. 64비트 모드에서 base-index 피연산자의 예를 작성하라.
[정답]
mov rax,[rbx+rdi]
[풀이]
RBX와 RDI를 더한 주소에 있는 QWORD를 읽는다.

====================================================================
11번. EBX가 행 인덱스, EDI가 열 인덱스인 32비트 정수 배열 myArray에서 해당 원소를 한 문장으로 EAX에 가져와라.
[정답]
mov eax,myArray[ebx+edi*4]    ; EBX가 행의 바이트 오프셋인 경우
[풀이]
교재 29쪽 방식은 EBX가 이미 행 번호*행 크기(바이트)인 경우이다. 문제의 EBX가 순수한 행 번호라면 일반적인 행 크기에 대해 한 명령으로 불가능하다. 예: 4열 배열이면 imul ebx,16을 먼저 실행한 뒤 위 MOV를 사용한다. 배열의 열 개수가 주어지지 않았으므로 이 조건을 명시한다.

====================================================================
12번. RBX가 행 인덱스, RDI가 열 인덱스인 64비트 정수 배열 myArray에서 해당 원소를 한 문장으로 RAX에 가져와라.
[정답]
; RBX가 행 바이트 오프셋인 경우, 심볼 주소가 disp32로 표현 가능한 환경
mov rax,myArray[rbx+rdi*8]
; 일반적인 x64 주소 모델에서는 배열 시작 주소를 미리 RBX에 반영:
; lea rbx,myArray / 행 바이트 오프셋을 RBX에 더한 뒤
; mov rax,[rbx+rdi*8]
[풀이]
QWORD는 8바이트. 순수 행 번호라면 행 크기를 곱하는 준비가 필요하고, 일반적인 Windows x64 이미지 주소는 심볼+인덱스를 직접 인코딩하지 못할 수 있다. 따라서 미리 행의 실제 주소를 구한 뒤 MOV 한 문장을 쓰는 방식이 안전하다.
