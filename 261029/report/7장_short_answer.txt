1번
다음 코드에서 a~d 각 이동/회전 명령 실행 후 AL 값은?

mov al,0D4h
shr al,1                  ; a
mov al,0D4h
sar al,1                  ; b
mov al,0D4h
sar al,4                  ; c
mov al,0D4h
rol al,1                  ; d

[정답]
a. AL = 6Ah
b. AL = EAh
c. AL = FDh
d. AL = A9h

[풀이]
D4h = 11010100b.
SHR: 왼쪽에 0을 채우므로 01101010b = 6Ah.
SAR: 최상위 부호 비트 1을 유지하므로 11101010b = EAh.
SAR 4회: 부호 있는 -44를 16으로 산술 시프트 → -3 = FDh.
ROL: 왼쪽 끝의 1이 오른쪽 끝으로 돌아와 10101001b = A9h.

2번
다음 코드에서 a~d 각 회전 명령 실행 후 AL 값은?

mov al,0D4h
ror al,3                  ; a
mov al,0D4h
rol al,7                  ; b
stc
mov al,0D4h
rcl al,1                  ; c
stc
mov al,0D4h
rcr al,3                  ; d

[정답]
a. AL = 9Ah
b. AL = 6Ah
c. AL = A9h (CF=1)
d. AL = 3Ah (CF=1)

[풀이]
ROR 3: 11010100b → 10011010b.
ROL 7: 8비트에서 오른쪽 1회 회전과 같아서 01101010b.
RCL 1: 초기 CF=1을 맨 오른쪽 비트로 넣고, 기존 최상위 비트는 CF로 이동.
RCR 3: 9비트 연결 고리(CF+AL)를 3회 오른쪽 회전.
  시작 CF:AL = 1:11010100
  1회 = 0:11101010
  2회 = 0:01110101
  3회 = 1:00111010

3번
곱셈 실행 후 AX와 DX는?
mov dx,0
mov ax,222h
mov cx,100h
mul cx

[정답]
DX = 0002h
AX = 2200h

[풀이]
222h × 100h = 22200h. 16비트 MUL 결과는 DX:AX에 저장.
32비트 결과 00022200h를 분리하면 DX=0002h, AX=2200h.

4번
나눗셈 실행 후 AX는?
mov ax,63h
mov bl,10h
div bl

[정답]
AX = 0306h (AH=03h: 나머지 / AL=06h: 몫)

[풀이]
63h(99) / 10h(16) = 몫 6, 나머지 3.
8비트 DIV는 피제수 AX, 몫 AL, 나머지 AH를 사용.

5번
나눗셈 후 EAX, EDX는?
mov eax,123400h
mov edx,0
mov ebx,10h
div ebx

[정답]
EAX = 00012340h
EDX = 00000000h

[풀이]
32비트 DIV에서는 EDX:EAX가 64비트 피제수.
123400h / 10h = 12340h, 나머지 0.

6번
나눗셈 후 AX, DX는?
mov ax,4000h
mov dx,500h
mov bx,10h
div bx

[정답]
나눗셈 오버플로로 #DE(나눗셈 오류) 발생.
정상적인 최종 AX/DX 몫·나머지 값은 없음.

[풀이]
피제수 DX:AX = 05004000h.
05004000h / 0010h = 00500400h.
몫이 16비트 AX(최대 FFFFh)에 들어가지 않으므로 DIV가 예외 발생.

7번
다음 코드 실행 후 BX는?
mov bx,5
stc
mov ax,60h
adc bx,ax

[정답]
BX = 0066h

[풀이]
STC로 CF=1.
ADC는 BX ← BX + AX + CF = 5h + 60h + 1 = 66h.

8번
64비트 코드가 실행되면 어떤 일이 발생하는가?
.data
dividend_hi QWORD 00000108h
dividend_lo QWORD 33300020h
divisor     QWORD 00000100h
.code
mov rdx,dividend_hi
mov rax,dividend_lo
div divisor

[정답]
DIV에서 #DE(나눗셈 오버플로) 예외가 발생한다.
몫을 정상 출력하지 못하며, 별도 예외 처리가 없다면 프로그램이 중단된다.

[풀이]
64비트 DIV의 피제수는 RDX:RAX, 몫은 RAX.
RDX=108h, 나누는 수=100h이므로 상위 64비트가 나누는 수보다 큼.
이 경우 몫은 64비트에 들어가지 못한다.

9번
QWORD val1에서 val2를 빼려는 코드의 모든 논리 오류를 찾아 수정하라.

.data
val1   QWORD 20403004362047A1h
val2   QWORD 055210304A2630B2h
result QWORD 0

원래 의도: 8바이트를 차례로 빌림(CF)을 전달하며 빼고 result에 보관.
원본의 핵심 오류: mov esi,val1 / mov edi,val2, 방향이 잘못된 DEC,
                val1을 덮어쓰는 저장, 32비트 LOOP용 ECX 미완전 설정.

[정답 — 수정 코드]
.data
val1   QWORD 20403004362047A1h
val2   QWORD 055210304A2630B2h
result QWORD 0
.code
    mov esi,OFFSET val1
    mov edi,OFFSET val2
    mov ebx,OFFSET result
    mov ecx,8
    clc
L1:
    mov al,BYTE PTR [esi]
    sbb al,BYTE PTR [edi]
    mov BYTE PTR [ebx],al
    inc esi
    inc edi
    inc ebx
    loop L1

결과: result = 1AEE1FD3EBFA16EFh.

[풀이]
리틀 엔디언이므로 하위 바이트부터(주소가 낮은 곳부터) 계산한다.
ESI/EDI/EBX에는 각각 변수의 주소(OFFSET)를 넣어야 한다.
SBB는 이전 자리의 CF(빌림)를 다음 자리 계산에 반영한다.
INC와 LOOP는 CF를 변경하지 않으므로 빌림을 유지할 수 있다.

10번
64비트에서 다음 명령 실행 후 RAX의 16진수 값은?
.data
multiplicand QWORD 0001020304050000h
.code
imul rax,multiplicand,4

[정답]
RAX = 0004080C10140000h

[풀이]
0001020304050000h × 4 = 0004080C10140000h.
IMUL의 3피연산자 형식: 목적지 = 원본 × 즉시값.
이 값은 부호 있는 64비트 범위 안이므로 오버플로 없이 저장된다.
