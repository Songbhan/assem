  
1번
DWORD 변수 three의 상위 WORD와 하위 WORD를 서로 교환하는
MOV 명령어들의 순서를 작성하라.

[정답]

mov ax, WORD PTR three
mov bx, WORD PTR three+2
mov WORD PTR three, bx
mov WORD PTR three+2, ax

[풀이]
DWORD는 32비트이고 WORD는 16비트이다.

three의 메모리 구조:
three      -> 하위 16비트
three + 2  -> 상위 16비트

먼저 하위 WORD와 상위 WORD를 각각 AX, BX에 보관한 뒤
반대 위치에 저장하면 된다.

주의:
MOV는 일반적인 경우 메모리 -> 메모리 전송이 불가능하므로
중간에 레지스터를 사용해야 한다.


  
2번
XCHG 명령을 최대 3번만 사용하여 네 개의 8비트 레지스터에 들어 있는
값의 순서를

A, B, C, D

에서

B, C, D, A

로 바꾸어라.

AL=A, BL=B, CL=C, DL=D라고 가정한다.

[정답]

xchg al, bl
xchg bl, cl
xchg cl, dl

  
3번
전송되는 메시지는 데이터 바이트와 결합했을 때 전체 1비트의 개수가
짝수가 되도록 패리티 비트를 포함하는 경우가 많다.

AL에 다음 메시지 바이트가 들어 있다고 하자.

01110101b

Parity Flag와 산술 명령어를 이용하여 이 메시지 바이트의 패리티가
짝수인지 홀수인지 판별하는 방법을 보여라.

[정답]

mov al,01110101b
add al,0

; PF = 0 -> 홀수 패리티

[풀이]
01110101b에 들어 있는 1의 개수는 5개이다.

5는 홀수이므로:
PF = 0

x86의 Parity Flag:
- 결과의 하위 8비트에서 1의 개수가 짝수 -> PF=1
- 결과의 하위 8비트에서 1의 개수가 홀수 -> PF=0

add al,0은 AL의 값은 바꾸지 않으면서 플래그를 갱신할 수 있다.

분기까지 작성하면:

add al,0
jp  EvenParity
jnp OddParity

현재 값에서는 OddParity 쪽으로 간다.

또한 짝수 패리티를 만들기 위한 별도의 parity bit가 필요하다면
현재 1의 개수가 홀수이므로 parity bit는 1이어야 한다.


  
4번
BYTE 크기의 피연산자를 사용하여 두 음수를 더하고
Overflow Flag가 설정되도록 하는 코드를 작성하라.

[정답]

mov al,-100
add al,-50        ; OF = 1

[풀이]
수학적으로:
-100 + (-50) = -150

signed byte 범위:
-128 ~ +127

-150은 범위를 벗어나므로 signed overflow가 발생한다.

8비트 결과는 wrap-around되어 양수처럼 보이게 되고:
OF = 1


  
5번
덧셈을 사용하여 Zero Flag와 Carry Flag를 동시에 1로 만드는
두 개의 명령어를 작성하라.

[정답]

mov al,0FFh
add al,1          ; AL=00h, ZF=1, CF=1

[풀이]
FFh + 1 = 100h

AL은 8비트이므로 하위 8비트만 남아:
AL = 00h

결과가 0:
ZF = 1

8비트 범위를 넘어가는 carry가 발생:
CF = 1


  
6번  
뺄셈을 사용하여 Carry Flag를 설정하는 두 개의 명령어를 작성하라.

[정답]

mov al,3
sub al,4          ; CF = 1

[풀이]
unsigned 기준으로 3에서 4를 빼려면 borrow가 필요하다.

3 - 4 -> unsigned borrow 발생

따라서:
CF = 1


  
7번 
다음 산술식을 어셈블리 언어로 구현하라.

EAX = -val2 + 7 - val3 + val1

val1, val2, val3는 모두 32비트 정수 변수라고 가정한다.

[정답]

mov eax,val2
neg eax
add eax,7
sub eax,val3
add eax,val1

[풀이]
1) EAX = val2
2) NEG로 부호 반전 -> EAX = -val2
3) +7
4) -val3
5) +val1

최종:
EAX = -val2 + 7 - val3 + val1


  
8번
DWORD 배열을 순회하면서,
배율 인자(scale factor)를 사용하는 인덱스 주소지정 방식으로
모든 원소의 합을 계산하는 반복문을 작성하라.

[정답]
배열 이름을 arrayD라고 가정한다.

mov eax,0
mov ecx,LENGTHOF arrayD
mov esi,0

L1:
    add eax,arrayD[esi*4]
    inc esi
    loop L1

[풀이]
DWORD 하나의 크기 = 4바이트

따라서:
arrayD[esi*4]

에서 ESI가 0,1,2,3으로 증가할 때 실제 주소는

arrayD+0
arrayD+4
arrayD+8
arrayD+12

순서로 이동한다.

EAX에는 전체 합이 저장된다.

※ 배열 원소들의 합이 32비트 범위를 넘어갈 수 있다면
   별도의 overflow/carry 처리도 필요하다.


  
9번
다음 식을 어셈블리 언어로 구현하라.

AX = (val2 + BX) - val4

val2와 val4는 16비트 정수 변수이다.

[정답]

mov ax,val2
add ax,bx
sub ax,val4


  
10번
Carry Flag와 Overflow Flag를 동시에 1로 만드는
두 개의 명령어를 작성하라.

[정답]

mov al,80h
add al,80h        ; CF=1, OF=1

[풀이]
unsigned 관점:
80h + 80h = 100h

8비트 범위를 넘으므로:
CF = 1

signed 관점:
80h = -128

-128 + -128 = -256

signed byte 범위 -128~+127을 벗어나므로:
OF = 1

8비트 AL에는 최종적으로 00h가 남는다.


  
11번  
INC와 DEC 명령을 실행한 후,
Zero Flag를 이용하여 unsigned overflow를 나타낼 수 있는
명령어의 순서를 작성하라.

[INC의 경우 - 직접 검출 가능]

mov al,0FFh
inc al
jz  IncOverflow

[풀이]
unsigned 8비트 최대값:
FFh = 255

255를 INC하면:
FFh + 1 -> 00h

결과가 0이므로:
ZF = 1

따라서 INC에서 최대값 -> 0으로 wrap-around한 경우는
JZ로 직접 검출할 수 있다.

13번
다음 각 명령어가 실행된 후 EAX의 값은 무엇인가?

mov eax,TYPE myBytes       ; a.
mov eax,LENGTHOF myBytes   ; b.
mov eax,SIZEOF myBytes     ; c.
mov eax,TYPE myWords       ; d.
mov eax,LENGTHOF myWords   ; e.
mov eax,SIZEOF myWords     ; f.
mov eax,SIZEOF myString    ; g.

[정답]

a. EAX = 00000001h
b. EAX = 00000004h
c. EAX = 00000004h
d. EAX = 00000002h
e. EAX = 00000004h
f. EAX = 00000008h
g. EAX = 00000005h

[풀이]

myBytes BYTE 10h,20h,30h,40h

BYTE 하나의 크기:
TYPE myBytes = 1

원소 개수:
LENGTHOF myBytes = 4

총 크기:
SIZEOF myBytes = 1 * 4 = 4


myWords WORD 3 DUP(?),2000h

WORD 하나의 크기:
TYPE myWords = 2

3 DUP(?) = WORD 3개
2000h = WORD 1개

따라서:
LENGTHOF myWords = 4

총 크기:
SIZEOF myWords = 2 * 4 = 8


myString BYTE "ABCDE"

문자 5개이므로:
SIZEOF myString = 5
