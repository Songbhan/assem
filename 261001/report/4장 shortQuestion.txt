1번
다음 코드에서 (a), (b)로 표시된 각 명령어가 실행된 후
EDX의 값은 무엇인가?

.data
one WORD 8002h
two WORD 4321h
.code
mov   edx,21348041h
movsx edx,one          ; (a)
movsx edx,two          ; (b)

[정답]
(a) EDX = FFFF8002h
(b) EDX = 00004321h

[풀이]
MOVSX는 부호 확장(Sign Extension)을 수행한다.

one = 8002h
16비트에서 최상위 비트가 1이므로 음수로 취급된다.
32비트로 부호 확장:
8002h -> FFFF8002h

two = 4321h
최상위 비트가 0이므로 양수이다.
32비트로 부호 확장:
4321h -> 00004321h


2번 
다음 명령어들이 실행된 후 EAX의 값은 무엇인가?

mov eax,1002FFFFh
inc ax

[정답]
EAX = 10020000h

[풀이]
처음:
EAX = 1002FFFFh
AX  = FFFFh

INC AX:
FFFFh + 1 = 0000h  (16비트에서 wrap-around)

EAX의 상위 16비트 1002h는 그대로이므로:
EAX = 10020000h


3번
다음 명령어들이 실행된 후 EAX의 값은 무엇인가?
mov eax,30020000h
dec ax

[정답]
EAX = 3002FFFFh

[풀이]
처음:
EAX = 30020000h
AX  = 0000h

DEC AX:
0000h - 1 = FFFFh

상위 16비트 3002h는 그대로:
EAX = 3002FFFFh

4번
다음 명령어들이 실행된 후 EAX의 값은 무엇인가?

mov eax,1002FFFFh
neg ax

[정답]
EAX = 10020001h

[풀이]
AX = FFFFh = signed 16비트에서 -1

NEG AX는 0 - AX:
-(-1) = +1

AX = 0001h

상위 16비트 1002h는 그대로:
EAX = 10020001h


5번
다음 명령어들이 실행된 후 Parity Flag(PF)의 값은 무엇인가?

mov al,1
add al,3

[정답]
PF = 0

[풀이]
AL = 1 + 3 = 4 = 04h

04h의 이진수:
0000 0100

1인 비트의 개수는 1개 = 홀수.

x86의 PF는 결과의 최하위 바이트에서
1인 비트의 개수가 "짝수"이면 1,
"홀수"이면 0이다.

따라서:
PF = 0



6번
다음 명령어들이 실행된 후 EAX의 값과 Sign Flag(SF)의 값은 무엇인가?

mov eax,5
sub eax,6

[정답]
EAX = FFFFFFFFh
SF = 1

[풀이]
5 - 6 = -1

32비트 2의 보수에서 -1:
FFFFFFFFh

결과의 최상위 비트가 1이므로:
SF = 1



7번
AL의 값은 signed byte(부호 있는 8비트 정수)로 사용하려고 한다.
Overflow Flag가 AL의 최종 값이 유효한 signed 범위에 있는지
판단하는 데 어떻게 도움이 되는지, 또는 도움이 되지 않는지 설명하라.

mov al,-1
add al,130

[정답 - 실제 x86 동작 기준]
AL = 81h
signed 값으로는 -127
OF = 0

하지만 OF만으로는 사용자가 "양수 +130"을 넣으려 했다는 오류를 잡아낼 수 없다.

[풀이]
signed byte 범위:
-128 ~ +127

처음:
AL = -1 = FFh

130(decimal) = 82h

8비트 패턴 82h를 signed byte로 해석하면:
82h = -126

CPU가 실제로 수행하는 8비트 덧셈:
FFh + 82h = 181h
하위 8비트만 남기면:
AL = 81h

81h는 signed byte로 -127이다.

두 피연산자를 8비트 signed 값으로 보면:
-1 + (-126) = -127

유효한 범위 안이므로:
OF = 0

핵심:
+130 자체가 signed byte로 표현할 수 없는 값이다.
따라서 이 상황에서 OF는 "원래 사용자가 +130을 의도했다"는 사실까지 알 수 없다.
OF는 CPU에 실제로 들어간 비트 패턴을 기준으로 동작한다.



8번
다음 명령어가 실행된 후 RAX에는 어떤 값이 들어가는가?

mov rax,44445555h

[정답]
RAX = 0000000044445555h

[풀이]
RAX는 64비트 레지스터이다.
44445555h를 64비트로 표현하면 상위 자리를 0으로 채운다.

00000000 44445555h



9번
다음 명령어들이 실행된 후 RAX에는 어떤 값이 들어가는가?

.data
dwordVal DWORD 84326732h
.code
mov eax,0FFFFFFFF00000000h
mov eax,dwordVal

mov eax,dwordVal

RAX = 0000000084326732h

[풀이]
처음:
RAX = FFFFFFFF00000000h

그 다음 수정된 명령:
mov eax,dwordVal

EAX = 84326732h

x86-64에서 EAX 같은 32비트 범용 레지스터에 값을 쓰면
RAX의 상위 32비트는 자동으로 0이 된다.

따라서:
RAX = 0000000084326732h





10번
다음 명령어들이 실행된 후 EAX에는 어떤 값이 들어가는가?

.data
dVal DWORD 12345678h
.code
mov ax,3
mov WORD PTR dVal+2,ax
mov eax,dVal

[정답]
EAX = 00035678h

[풀이]
dVal = 12345678h

리틀 엔디언 메모리 배치:
주소+0 : 78h
주소+1 : 56h
주소+2 : 34h
주소+3 : 12h

mov ax,3
AX = 0003h

mov WORD PTR dVal+2,ax
dVal의 +2 위치부터 2바이트에 0003h를 저장한다.

메모리:
78 56 03 00

따라서 DWORD 값:
00035678h

mov eax,dVal
EAX = 00035678h



11번
다음 명령어들이 실행된 후 EAX에는 어떤 값이 들어가는가?

.data
dVal DWORD ?
.code
mov dVal,12345678h
mov ax,WORD PTR dVal+2
add ax,3
mov WORD PTR dVal,ax
mov eax,dVal

[정답]
EAX = 12341237h

[풀이]
1) dVal = 12345678h

2) mov ax,WORD PTR dVal+2
   dVal의 상위 WORD를 읽는다.
   AX = 1234h

3) add ax,3
   AX = 1237h

4) mov WORD PTR dVal,ax
   dVal의 하위 WORD에 1237h를 저장한다.
   기존 상위 WORD 1234h는 그대로이다.

따라서:
dVal = 12341237h

5) mov eax,dVal
EAX = 12341237h





12번예/아니오:
양의 정수와 음의 정수를 더할 때 Overflow Flag를 1로 만드는 것이 가능한가?

[정답]
아니오 (No)

[풀이]
signed 덧셈에서 OF는
"같은 부호의 두 수를 더했는데 결과의 부호가 반대로 나올 때" 발생한다.

양수 + 음수는 서로 부호가 다르므로 signed overflow가 발생하지 않는다.





13번
예/아니오:
음의 정수 + 음의 정수를 했는데 결과가 양수가 되었다면
Overflow Flag가 설정되는가?

[정답]
예 (Yes)

[풀이]
음수 + 음수의 정상적인 결과는 음수여야 한다.
그런데 양수가 나왔다면 표현 가능한 signed 범위를 넘은 것이다.

따라서:
OF = 1


14번



예/아니오:
NEG 명령어가 Overflow Flag를 설정하는 것이 가능한가?

[정답]
예 (Yes)

[풀이]
가장 작은 음수는 같은 비트 수의 양수로 바꿀 수 없다.

예: 8비트 signed
-128 = 80h

neg al을 수행해 +128을 만들려고 해도
8비트 signed의 최대값은 +127이다.

따라서:
OF = 1

같은 원리:
16비트 8000h,
32비트 80000000h 등에서도 발생한다.


15번
예/아니오:
Sign Flag(SF)와 Zero Flag(ZF)가 동시에 1이 될 수 있는가?

[정답]
아니오 (No)

[풀이]
ZF = 1이면 결과가 0이다.

0의 최상위 비트는 0이므로:
SF = 0

따라서 같은 결과에 대해 SF=1, ZF=1이 동시에 될 수 없다.

16번
다음 명령어 각각이 유효한(valid) 명령인지 판단하라.

a. mov   ax,var1
b. mov   ax,var2
c. mov   eax,var3
d. mov   var2,var3
e. movzx ax,var2
f. movzx var2,al
g. mov   ds,ax
h. mov   ds,1000h

[정답]
a. Invalid
b. Valid
c. Invalid
d. Invalid
e. Invalid
f. Invalid
g. Valid
h. Invalid

[풀이]

a. mov ax,var1
   AX = 16비트
   var1 = 8비트 SBYTE
   MOV는 피연산자 크기가 맞아야 한다.
   -> Invalid

b. mov ax,var2
   AX = 16비트
   var2 = 16비트 WORD
   -> Valid

c. mov eax,var3
   EAX = 32비트
   var3 = 16비트 SWORD
   일반 MOV로 크기가 다른 값을 직접 옮길 수 없다.
   -> Invalid

d. mov var2,var3
   메모리 -> 메모리 MOV는 일반적으로 허용되지 않는다.
   -> Invalid

e. movzx ax,var2
   MOVZX는 목적지가 원본보다 더 커야 한다.
   AX와 var2는 둘 다 16비트이다.
   -> Invalid

f. movzx var2,al
   MOVZX의 목적지는 레지스터여야 한다.
   var2는 메모리이다.
   -> Invalid

g. mov ds,ax
   세그먼트 레지스터 DS에 16비트 레지스터 AX의 값을 옮길 수 있다.
   -> Valid

h. mov ds,1000h
   세그먼트 레지스터로 즉시값(immediate)을 직접 MOV할 수 없다.
   -> Invalid




17번
다음 명령어들을 순서대로 실행했을 때
각 명령어의 목적지 피연산자의 값을 16진수로 쓰라.

mov al,var1          ; a.
mov ah,[var1+3]      ; b.

[정답]
a. AL = FCh
b. AH = 01h

[풀이]
var1:
offset 0 -> -4 = FCh
offset 1 -> -2 = FEh
offset 2 ->  3 = 03h
offset 3 ->  1 = 01h

a)
mov al,var1
첫 번째 바이트 -4를 가져온다.
AL = FCh

b)
mov ah,[var1+3]
var1에서 3바이트 뒤의 값은 1이다.
AH = 01h



18번
다음 명령어들을 순서대로 실행했을 때
각 명령어의 목적지 피연산자의 값은 무엇인가?

mov ax,var2          ; a.
mov ax,[var2+4]      ; b.
mov ax,var3          ; c.
mov ax,[var3-2]      ; d.

[정답]
a. AX = 1000h
b. AX = 3000h
c. AX = FFF0h
d. AX = 4000h

[풀이]
var2는 WORD 배열이므로 원소 하나 = 2바이트.

주소:
var2+0 -> 1000h
var2+2 -> 2000h
var2+4 -> 3000h
var2+6 -> 4000h

a)
mov ax,var2
AX = 1000h

b)
mov ax,[var2+4]
4바이트 이동 = WORD 2개 이동
AX = 3000h

c)
var3의 첫 값은 -16
16비트 2의 보수:
-16 = FFF0h
AX = FFF0h

d)
var3는 var2 바로 다음에 선언되어 있다.
[var3-2]는 var3보다 2바이트 앞,
즉 var2의 마지막 WORD를 가리킨다.

AX = 4000h



19번
다음 명령어들을 순서대로 실행했을 때
각 명령어의 목적지 피연산자의 값은 무엇인가?

mov   edx,var4       ; a.
movzx edx,var2       ; b.
mov   edx,[var4+4]   ; c.
movsx edx,var1       ; d.

[정답]
a. EDX = 00000001h
b. EDX = 00001000h
c. EDX = 00000002h
d. EDX = FFFFFFFCh

[풀이]

a)
var4의 첫 DWORD = 1
EDX = 00000001h

b)
var2의 첫 WORD = 1000h

MOVZX는 Zero Extension:
1000h -> 00001000h

EDX = 00001000h

c)
var4는 DWORD 배열이므로 원소 하나 = 4바이트.

var4+0 -> 1
var4+4 -> 2

EDX = 00000002h

d)
var1의 첫 값 = -4 = FCh

MOVSX로 8비트 signed 값을 32비트로 부호 확장:
FCh -> FFFFFFFCh

EDX = FFFFFFFCh
